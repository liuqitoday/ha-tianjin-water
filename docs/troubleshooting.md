# 故障排查

先查看「设置 → 设备与服务 → Tianjin Water」的条目状态。
如集成仍加载，采集状态实体提供 `last_success`、`history_updated`、`request_count`、
`consecutive_errors` 和 `stop_reason`；时间包含时区。请求计数为当前客户端实例的计数，重载后会重新开始。

| 现象 | 含义与处理 |
| --- | --- |
| `running`，最近成功时间正常推进 | 查询成功；余额不变也应更新成功时间 |
| `retrying` | 临时网络、限流或服务端错误，下次轮询再试 |
| `authentication_required` / `invalid_auth` | 明确认证拒绝；重新进入官方页面抓取新 SESSION，再在原条目中重新认证 |
| `unexpected_http_status`（例如 404） | 不能直接判定过期；先确认网页能查询、户号仍绑定在相同微信用户下，再重新配置 |
| `unexpected_response`、字段或格式错误 | 上游响应无法可靠解释，已停止；提供静态错误码，不要反复刷新 |
| `repeated_connection_error` | 连续三次连接失败后停止；恢复网络/服务后通过重新配置验证 |
| 重启后条目加载失败 | 停止标记会持久化，重启不会解除；按停止原因处理后重新配置 |
| 找不到集成 | 检查 HA 版本和目录层级，重启 HA；安装目录下须直接有 manifest.json |
| 能看余额却没有水表 | 当前仅支持后台返回的 NB 表；IC 表及其他类型不按 NB 语义解析 |
| 用量长时间不变 | 抄表按周期发生，不是每日实时数据；查看最近抄表日期 |
| 相同旧 SESSION 被拒绝再次验证 | 曾明确认证失败的凭据不会重试，需要成功登录后的新 SESSION |

本集成停止的是该水务账户的上游请求，不是整个 Home Assistant。
停止后使用原条目的「重新配置」或重新认证入口，成功验证会清除停止标记并保留设备标识。
暂停正常采集可以直接禁用配置条目。

## 提交问题

提供 HA Core 版本、集成版本、安装方式、静态错误码、开始出现问题的大致时间，
以及官方页面是否仍能查询即可。必要时从集成页面下载诊断，**先自行检查完整文件**再决定分享哪些字段。
HA 可能给诊断增加外围系统信息，本项目的脱敏范围是自己生成的诊断部分。

不要粘贴 config entry、完整 HA 状态、注册表、`.storage`、日志全文、HAR、Cookie 或包含户号的截图。
本项目无需维护者拿到你的 SESSION 来复现问题；可用虚构数据描述响应结构。
发现可能泄露凭据的问题请使用 [私密安全报告](../SECURITY.md)。
